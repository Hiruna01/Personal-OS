# Manual verification — Phases 0–3

Use a dedicated development Supabase project and synthetic data. Record the browser, viewport, result, and any issue for each journey.

1. **Owner access:** request `/app` and `/api/assets/<id>` while signed out. Sign in as the provisioned owner, sign out, and check that private pages are unavailable. Create an unrelated Auth account administratively and verify it has no workspace access. Do not enable public registration.
2. **Database boundaries:** using anonymous and unrelated authenticated sessions, attempt direct reads/writes on every public domain table and storage bucket. They must fail or return no rows. Try mismatching module, lecture, project, workspace, and asset parents; foreign keys must reject them. Verify that an owner client cannot insert another workspace or change `owner_user_id`.
3. **Recovery:** request a password reset, follow the email link, set a matching password of at least 12 characters, and sign in again. Expired and reused recovery links must show the unavailable message. Check the configured site URL, redirect allowlist, and recovery email template.
4. **Structure:** enter an academic profile. Create/edit semesters of each status. Switch Current from one Active semester to another. Verify only one stays Current. Reject end-before-start dates and Current with Planned/Completed status. Add modules, reject duplicate normalised codes within a semester, and allow the same code in a different semester.
5. **Lectures:** add/edit lecture titles, topics, optional dates, and status. Reorder both directions and reload to check persistence. Open a lecture-note link and check the lecture remains in its chosen study status. Verify continuation links derive only from Studying lectures in Current semester.
6. **Notes and thumbnails:** save multiple external links. Upload JPEG, PNG, and WebP thumbnails. Reject SVG, renamed invalid image data, files over 2 MiB, and images below 32 × 32 pixels. Verify private thumbnails load only as owner and broken external images have a fallback. Replace an image and reload.
7. **Quiz import:** download `quiz.md`, upload it under a lecture, preview all questions, and save. Repeat at module exam level. Verify question order, code, mathematics, options, answers, and explanations. Reveal questions independently, optionally select answers, and reload to reset local state.
8. **Malformed quizzes:** try missing/wrong format marker, missing/duplicate/nonsequential question numbers, unsupported type, missing/empty answer or explanation, reserved heading misuse, duplicate/missing option labels, one option, and unmatched MCQ answer. Include apparent question headings inside a code fence; those must remain code. Check useful question/line feedback and no partial saved document.
9. **Source editing/replacement:** edit and replace quiz source, re-preview, and save. Open one document in two tabs; save tab A, then attempt tab B. The stale update must fail without overwriting A. Repeat malformed replacement and confirm the prior source and JSON remain intact. Cancel a preview and check nothing was saved.
10. **Ordinary documents:** upload Tutorial, Practical, Essay, Exam questions, and Project brief examples through their appropriate entry points. Include headings, author numbering, tables, wide code, inline/display math, and answers. They should appear exactly where written without quiz extraction. Edit, replace, and delete these documents.
11. **Content safety:** upload scripts/raw HTML/MDX, `javascript:` and `data:` links, relative/local images, image references, hostile math commands, and code containing apparent structure. Raw code must not execute; unsafe links/images must be disabled and warnings should be shown. HTTPS images load in the browser, never via server link fetching.
12. **Exam/project boundaries:** add/edit past-paper and solution links with year/type. Create a minimal project and add/read briefs. Verify there are no team, milestone, scheduling, mark, scoring, or sharing controls.
13. **Visual/accessibility:** review desktop, 768px, and 360px. Use the keyboard through navigation, dialogs, tabs, file selection, radio options, and reveals. Confirm dialog focus return and Escape, visible focus, labels, errors, loading, empty, selected, disabled, hover, and broken-image states. Check code/table/math overflow and reduced motion.
14. **Production boundary:** run `npm run build` and `npm start`, then request `/preview` and nested preview URLs. They must be unavailable even with `ENABLE_DEMO=true`. Authenticated pages and private asset responses must use private/no-store caching. Confirm no administrative key is present in browser assets.

Before using real study records, back up the database and thumbnail objects separately and practise restoring both into a nonproduction Supabase project.
